# A-32.1

**Assumption.** The test script quotes its glob with double quotes, `node --test "tests/**/*.test.js"`, so that Node, not the shell, expands it on every OS. This revises the single-quoted script in A-8.8.

**Reason.** On Windows, pnpm runs package scripts through `cmd.exe`, which does not treat single quotes as quotes. Node got `'tests/**/*.test.js'` with the quotes on it, matched no files, and exited 0 with `tests 0`, so `make test` and the pre-push `make verify` hook passed without running a test. Both `cmd.exe` and `sh` strip double quotes and leave the glob unexpanded.

**Effect if incorrect.** If a contributor's pnpm uses a shell that expands globs inside double quotes, Node receives a list of files instead of the pattern and still runs them all. Nothing changes at runtime.

**Validation or mitigation.** `pnpm run test` reports the same test count on Windows (`cmd.exe`) and under `sh`, and that count matches `node --test "tests/**/*.test.js"` run directly. A count of 0 means the glob reached Node with its quotes on.
