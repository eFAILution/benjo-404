# A-20.2

**Assumption.** In Dragon Tail and Code Crossing a tap acts when the finger lifts, not when it lands, because a swipe also starts with a press. In Dragon Tail the tap turns toward the tapped side; in Code Crossing it hops toward the tapped spot along the longer axis. A swipe wins over a tap.

**Reason.** Acting on the press made every swipe also queue a move toward where the finger first landed, so a swipe up could send Benjo down. The shell reports a tap only as a short `primary` pulse and a swipe as a direction, with no shared tap-or-swipe gesture.

**Effect if incorrect.** If the roughly 0.1 s delay on a tap feels slow on real phones, the shell could report a tap with its position (for example `input.tap = { x, y }` for one tick) so games can act on it at once; that is a shell change with its own issue.

**Validation or mitigation.** Each game's module tests cover tap and swipe. Try both games on a real phone.
