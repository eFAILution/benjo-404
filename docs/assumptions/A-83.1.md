# A-83.1

**Assumption.** Bug Zapper is harder in a way players enjoy if later waves get bigger, the last bugs move fast, more bolts can be in the air, and bites vary. The numbers in `src/games/zapper/tuning.js`:
- **Block size:** 6x3 growing to 8x5, a column and a row every 2 waves.
- **Last bug:** moves 2.5 times as fast as the full block, with the cap raised to 220 px/s (150 with reduced motion).
- **Bolts:** 8, with a 0.18 s cooldown.
- **Bite timing:** gaps vary by up to 50% either way, and each bite falls at 0.75 to 1.3 times the wave's speed.
- **Aimed bites:** up to 45% are aimed at Benjo's column, starting in wave 2.
- **Bursts:** up to 30% of bites start a burst, starting in wave 3.

Columns are only added while the block spans at most 65% of the play width. Rows are only added while the block starts at least 6 drops above Benjo's row. So phones grow by rows, and a 320x240 screen keeps 6x3.

**Reason.** Play-testing found every wave played the same. The owner asked for more bugs per wave, faster bugs as they die, more than 3 shots on screen, and less predictable bites (#83). Waves 1 and 2 stay close to before: no aimed bites in wave 1 and no bursts before wave 3, so a first run is still gentle.

**Effect if incorrect.** If it's too hard, lower `AIM_MAX`, `BURST_MAX` or `FORM_SPEED_RAMP`. If it's too easy, raise them. Each is one constant. If 8 bolts make it too easy, raise `FIRE_COOLDOWN`.

**Validation or mitigation.** `tests/games/zapper/fairness.test.js` keeps the old test: an autopilot clears waves 1 and 2 in 60 s at five sizes, with and without reduced motion, without losing a life. Its lead now bounces off the wall the block turns at, because a fast last bug on a 2560 px screen otherwise outran it. A new test has the same autopilot clear five waves in 120 s at every size. `tests/games/zapper/waves.test.js` pins the block sizes, the room each block leaves, and the bite spread. Play it on a phone and a desktop for #19.
