# A-28.2

**Assumption.** Each game's `howto.js` describes its rules as the code has them on this branch. That includes which keys do what, which things to avoid or collect, and how a run ends. Numbers (points, seconds, lives, streak length) come from `tuning.js` constants, but the words are written by hand from the game's world, controls, and draw code.

**Reason.** No part of a game's code describes its own rules in words, so only a person or agent reading it can write the card. Pulling the numbers from tuning removes the drift that is most likely: a retuned score or timer.

**Effect if incorrect.** A wrong line teaches the wrong rule. For example, a tip saying a flyer can only be ducked when it can also be jumped would mislead players. A future rule change also needs a matching `howTo` edit, and `tests/games/howto.test.js` only checks shape and length, not meaning.

**Validation or mitigation.** The wording was checked against each game's `controls.js` (keys and gestures), `world.js` (scoring and what ends a run), and `draw.js` (which sprite or color each thing uses). Each game's owner should read its card once during review.
