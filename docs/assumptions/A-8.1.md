# A-8.1

**Assumption.** The built `dist/404.html` and its CSP header will be served by something in front of Webflow (an edge worker or reverse proxy that answers 404 responses with this file), not pasted into Webflow's page-level custom code box. Until that is confirmed, the build also writes `dist/embed/` (a body snippet plus separate JS, CSS, and font files) so the page can be assembled on a host that only allows separate assets.

**Reason.** The live 404 is a Webflow page. Webflow serves its own 404 and limits page-level custom code to a few thousand characters, which a game with fonts exceeds. A single file with hashed inline script and style is the only delivery that satisfies a strict CSP without a known origin for assets, so it is the primary artifact.

**Effect if incorrect.** If the site cannot put anything in front of Webflow and cannot host JS files as assets, the game cannot ship on the live domain and the deliverable stays a standalone page. The shell and games still work unchanged; only the deployment runbook changes.

**Validation or mitigation.** The owner confirms how `beast-code.com` is fronted (DNS, CDN, proxy) and whether Webflow asset hosting of `.js` and `.css` files is available on the site plan. The build keeps both outputs until then.
